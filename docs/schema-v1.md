# Schema v1

Status: **checked, 23 September 2026**. Implemented as EF Core migrations and tested against
PostgreSQL 16. The checks below passed on the complete ΚΗΜΔΗΣ probe. Not deployed yet, so the migrations can still be regenerated.

The schema is defined in `backend/src/IxnosData.Infrastructure/Persistence/` (the only place it
changes, [ADR 0002](adr/0002-database-as-only-integration-point.md)). The generated SQL is in
`contracts/db/schema.sql`, and the Python mirror is `pipeline/src/ixnos_data_pipeline/db/tables.py`,
checked against it in CI.

## Tables

| Table | Holds | Key |
| --- | --- | --- |
| `procurement_item` | Every record from both sources: requests, notices, awards, contracts, payments, commitments, spending approvals, final awards | `id`; unique `(source, source_id)` |
| `organisation` | Contracting authorities, seeded from the Διαύγεια register | shared ΚΗΜΔΗΣ/Διαύγεια ID |
| `contractor` | Winners and payees | `id`; unique `tax_id` when present |
| `item_contractor` | Which contractors a record names, and as what (winner or payee) | `(item_id, contractor_id, role)` |
| `item_link` | References between records, resolved or not | `(from_item_id, relation, to_source, to_source_id)` |
| `cpv_code`, `nuts_region` | Official code lists with Greek and English labels | code |
| `ingestion_run` | One row per pipeline run | `id` |

## Decisions and the evidence behind them

| Decision | Evidence (probes, September 2026) |
| --- | --- |
| **One table for all record kinds** (`kind` column), with the raw payload in `raw jsonb` | Search, alerts and organisation pages all span kinds. Keeping the payload means fields can be parsed later without refetching |
| **Search indexes title, description and CPV labels**, weighted A/B/C (`search` is generated by PostgreSQL; CPV labels live in `keywords`, searchable but not shown) | ΚΗΜΔΗΣ truncates titles at exactly 100 characters; line-item descriptions run to 14,000; an award titled «ειδών πυρασφάλειας» names «πυροσβεστήρες» only in its CPV label |
| `text_normalised` (title and description) and `search_key` (Greeklish key of the title) with trigram indexes | The Greek stemmer handles accents but not typos or Greeklish (see `docs/architecture.md`) |
| **`cpv_codes text[]` with a GIN index**, not a join table | 88% of records have one CPV code, but some have dozens; prefix filters (`3314%`) run on the array |
| **One `nuts_code` per record, no foreign key** | 98% of records have at most one region. 0.04% use foreign codes (delivery abroad) and ~7% only the country code "EL", which a foreign key would reject or mislabel |
| **Contractors in a join table**, not a `contractor_id` column | 2% of awards and contracts name a consortium (up to 5 members) |
| **Contractor `tax_id` unique only when valid** | 98.4% of contractor VAT numbers are valid Greek ones; foreign and malformed ones are stored without a tax ID |
| **Organisations keyed on the shared ID, `tax_id` not unique** | 99.8% of ΚΗΜΔΗΣ organisation keys are Διαύγεια register IDs; 224 VAT numbers are shared by several bodies |
| **Links store the target's source ID, and `to_item_id` when resolved** | References point to records outside the ingested window (older notices, commitments issued weeks earlier). They are kept and resolved as the targets arrive |
| `published_at` = the source's submission time | ΚΗΜΔΗΣ filters on it; records appear a median of 3 days after signing, so signing dates would make "new" records look old |
| Enums stored as snake_case text (`spending_approval`) | The Python pipeline reads and writes plain strings |

## Indexes

`procurement_item`: unique `(source, source_id)`; GIN on `search`, `cpv_codes`,
`text_normalised` (trigram) and `search_key` (trigram); B-tree on `published_at desc`,
`(organisation_id, published_at desc)`, `(kind, published_at desc)`, `nuts_code` and
`ingested_at` (the notifier's checkpoint). `item_link`: `(to_source, to_source_id)` for
resolution. `item_contractor`: `contractor_id`. `organisation`: `tax_id`, `parent_id`.

## Checked on the complete ΚΗΜΔΗΣ probe (23 September 2026)

Six months of notices and awards (274,488 records); details in
[`docs/data-sources/khmdhs.md`](data-sources/khmdhs.md).

1. **Coverage holds for notices and awards:** CPV and NUTS 100%, amounts 99.4% and 99.9%,
   deadlines on every notice. Confirmed.
2. **`amount_eur` is `totalCostWithoutVAT` for every kind**, awards included (filled on 100%);
   `budget` only fills a missing total. Confirmed as built.
3. **`signed_on` is always present** on notices and awards. Confirmed.
4. **Deadlines:** a median of 6.2 days after publication, 10% within 3.5 days. Phase 2 alerts
   must be at least daily.
5. **`nutsCodes` on notices is not redundant.** It is the place of performance, while
   `nutsCode` is the authority's address; they differ on 14.6% of notices (10.7% in another
   NUTS-2 region). **Decided:** `nuts_code` is the first place of performance when the record
   lists one (notices, contracts), else the authority's address (awards, requests, payments).
   The address stays in `raw`.
6. **Size:** 4.9 KB per record including indexes, so about 2.5 GB a year for notices and
   awards. Confirmed; `raw` can stay in the table through Phase 3.
